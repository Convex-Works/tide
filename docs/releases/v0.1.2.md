Fixes and hardening for self-hosted tide deployments.

```sh
docker run --rm --network host ghcr.io/convex-works/tide:0.1.2
```

The image and static binaries support linux/amd64 and linux/arm64.

## Changes

- The recording indicator no longer turns off while a recording is still
  running. A late or repeated end of an earlier recording turned it off
  for everyone in the room.
- Behind a trusted proxy, tide reads every `X-Forwarded-For` header line.
  A proxy that adds its own line, rather than appending to the client's,
  let a client choose its own rate-limit bucket. Addresses written with a
  port, such as `192.0.2.1:5678`, are now understood instead of counting
  every client as the proxy.
- `TIDE_DEV_MODE=true` refuses to start unless `TIDE_BASE_URL` is local:
  `localhost`, a loopback, private or link-local address, or a one-label
  host such as a Compose service name.
- The deployment guide on tide.convex.works installs the released image
  instead of building from the main branch.

## Upgrade

Change your container image tag to `ghcr.io/convex-works/tide:0.1.2`, then
run `docker compose pull && docker compose up -d`. For a binary install,
download the binary for your architecture, verify it against `SHA256SUMS`,
and replace the executable while the service is stopped.

Restarting tide ends active meetings and recordings. Schedule the upgrade
when no meeting is running. No configuration changes are required, unless a
deployment that is reachable from the internet runs with `TIDE_DEV_MODE=true`;
it now refuses to start. Remove that setting and set its secrets.
